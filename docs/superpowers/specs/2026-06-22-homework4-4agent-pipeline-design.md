**Date:** 2026-06-22  
**Author:** Vladyslav Nahirych  
**Status:** Approved

## Overview

Build a 4-agent CI-style pipeline that operates on a small Python CLI application (Budget Tracker). The pipeline: verifies bug research, fixes bugs, checks security, and generates unit tests — all via a single shell command.

---

## Decisions

| Question | Decision | Rationale |
|----------|----------|-----------|
| Mini app stack | Python CLI | Consistent with hw-1/2; minimal deps; easy to seed bugs |
| Single command | `run-pipeline.sh` | Universal, transparent, calls `claude -p` per agent |
| Artifacts | Real run via subagents | Homework requires "generated by the agents" |
| Models | Opus 4.8 (research+security), Sonnet 4.6 (fixer+tests) | Expensive models for judgment tasks, fast models for routine tasks |
| Mini app type | Budget Tracker CLI | Natural for division-by-zero + balance bug + SQL injection |

## Mini App: Budget Tracker CLI

**Commands:**
- `python3 src/budget.py add <amount> <category> <description>`
- `python3 src/budget.py list`
- `python3 src/budget.py search <keyword>`
- `python3 src/budget.py summary`

**Seeded bugs:**

| ID | File | Location | Bug | Consequence |
|----|------|----------|-----|-------------|
| BUG-001 | `calculator.py` | `average_spending()` | `total / len(transactions)` — no empty check | `ZeroDivisionError` on `summary` with no data |
| BUG-002 | `calculator.py` | `calculate_balance()` | `for t in transactions[1:]` — skips first transaction | Wrong balance always |

**Seeded vulnerability:**

| ID | File | Location | Type | Detail |
|----|------|----------|------|--------|
| SEC-001 | `storage.py` | `search()` | SQL Injection | `f"WHERE description LIKE '%{keyword}%'"` — raw interpolation |

**Test command:** `python3 -m pytest tests/ -v`

## Agents

### research-verifier.agent.md — claude-opus-4-8
**Justification:** Deep reasoning needed to cross-check every file:line reference in research against actual source files. Opus 4.8 handles long-context verification accurately.

**Responsibilities:**
1. Read `context/bugs/001/research/codebase-research.md`
2. Verify every file:line reference and snippet against source
3. Use `skills/research-quality-measurement.md` to rate quality
4. Write `context/bugs/001/research/verified-research.md` with: Verification Summary, Verified Claims, Discrepancies Found, Research Quality Assessment, References

### bug-fixer.agent.md — claude-sonnet-4-6
**Justification:** Routine implementation task (read plan → apply changes → run tests). Sonnet 4.6 is fast and cost-effective for structured execution.

**Responsibilities:**
1. Read `context/bugs/001/implementation-plan.md`
2. Apply changes per file (before/after as specified)
3. Run `python3 -m pytest tests/ -v` after each change
4. Write `context/bugs/001/fix-summary.md`: Changes Made, Overall Status, Manual Verification, References

### security-verifier.agent.md — claude-opus-4-8
**Justification:** Security analysis requires broad threat modeling and judgment about severity. Opus 4.8 catches subtle vulnerabilities that simpler models miss.

**Responsibilities:**
1. Read `context/bugs/001/fix-summary.md` and changed files
2. Scan for: injection, hardcoded secrets, insecure comparisons, missing validation, unsafe deps
3. Rate findings: CRITICAL / HIGH / MEDIUM / LOW / INFO
4. Write `context/bugs/001/security-report.md` only (no code edits)

### unit-test-generator.agent.md — claude-sonnet-4-6
**Justification:** Test scaffolding for known changes is a routine task. Sonnet 4.6 generates idiomatic pytest tests efficiently.

**Responsibilities:**
1. Read `context/bugs/001/fix-summary.md` and changed files
2. Use `skills/unit-tests-FIRST.md` — all tests must satisfy FIRST
3. Generate tests only for new/changed code
4. Run `python3 -m pytest tests/ -v` — all must pass
5. Write `context/bugs/001/test-report.md`

## Skills

### research-quality-measurement.md

| Level | Label | Criteria |
|-------|-------|----------|
| 5 | EXCELLENT | All file:line refs valid, snippets match source, no missed bugs |
| 4 | GOOD | ≥90% refs valid, minor discrepancies only |
| 3 | ACCEPTABLE | ≥70% refs valid, discrepancies non-critical |
| 2 | POOR | <70% refs valid or critical bugs missed |
| 1 | INVALID | References don't exist or are completely wrong |

### unit-tests-FIRST.md

| Principle | Requirement |
|-----------|-------------|
| **F**ast | Each test < 100ms, no real I/O — use in-memory SQLite |
| **I**ndependent | Tests don't depend on each other; order doesn't matter |
| **R**epeatable | Same result in any environment |
| **S**elf-validating | Pass/Fail without manual inspection |
| **T**imely | Tests only for new/changed code from fix-summary |

## Pipeline Script

`run-pipeline.sh` invokes agents sequentially via `claude -p`:

```bash
#!/usr/bin/env bash
set -e
BUGS_DIR="context/bugs/001"

echo "=== Step 1: Research Verifier (claude-opus-4-8) ==="
claude -p --model claude-opus-4-8 \
  --system-prompt "$(cat agents/research-verifier.agent.md)" \
  "Verify $BUGS_DIR/research/codebase-research.md and write $BUGS_DIR/research/verified-research.md"

echo "=== Step 2: Bug Fixer (claude-sonnet-4-6) ==="
claude -p --model claude-sonnet-4-6 \
  --system-prompt "$(cat agents/bug-fixer.agent.md)" \
  "Read $BUGS_DIR/implementation-plan.md, apply fixes, write $BUGS_DIR/fix-summary.md"

echo "=== Step 3: Security Verifier (claude-opus-4-8) ==="
claude -p --model claude-opus-4-8 \
  --system-prompt "$(cat agents/security-verifier.agent.md)" \
  "Read $BUGS_DIR/fix-summary.md and changed files, write $BUGS_DIR/security-report.md"

echo "=== Step 4: Unit Test Generator (claude-sonnet-4-6) ==="
claude -p --model claude-sonnet-4-6 \
  --system-prompt "$(cat agents/unit-test-generator.agent.md)" \
  "Read $BUGS_DIR/fix-summary.md, generate tests in tests/, write $BUGS_DIR/test-report.md"

echo "=== Pipeline complete ==="
python3 -m pytest tests/ -v
```

## Execution Plan Summary

1. Create `src/` — mini app with seeded bugs
2. Create `context/bugs/001/` — pre-seeded research and plan
3. Create `agents/*.agent.md` — all 4 agent definitions
4. Create `skills/*.md` — research-quality-measurement + unit-tests-FIRST
5. Create `run-pipeline.sh`
6. Run pipeline (via subagents in this session):
   - Research Verifier → `verified-research.md`
   - Bug Fixer → fixes `src/` + `fix-summary.md`
   - Security Verifier → `security-report.md`
   - Unit Test Generator → `tests/test_budget.py` + `test-report.md`
7. Run `python3 -m pytest tests/ -v` — all tests must pass
8. Write `README.md` + `HOWTORUN.md`
9. Take/document screenshots
